# Переход на обновлённый UI-кит

Эта статья описывает изменения текущей ветки редизайна: ThreeColumns, SearchInput, ConfigTable, пять базовых полей формы и Select/TreeSelect/AutoComplete, переключатели и даты, ConfigForm, массивы и словари, CodeEditor, LayoutMenu и LayoutSider. Она не означает, что новая версия пакета уже опубликована. Номер версии и выпуск фиксируются отдельно в CHANGELOG.

PcsKit и ReactJsonView исключены из редизайна. Главная и служебные страницы также обновлены; изменения описаны в разделе 9.

## Что сохраняется

Публичные компоненты и прежние обязательные параметры сохраняются. Приложение по-прежнему управляет данными, поиском, выбранными элементами и бизнес-действиями. Column и ConfigTable не выполняют запросы к API и не фильтруют данные автоматически.

Базовые поля остаются на React Hook Form и Ant Design. Их размеры, радиусы, цвета и фокус сохраняют стандартный вид Ant Design, чтобы сочетаться с полями, которые приложение использует напрямую.

У текстовых полей сохранена обрезка пробелов при потере фокуса. Переданные onChange/onBlur по умолчанию по-прежнему перекрываются обработчиками React Hook Form. Новое поведение включается отдельными параметрами.

Сохранение API не означает сохранение всей геометрии: рабочие области ThreeColumns и ConfigTable получили новый вид по умолчанию.

## ThreeColumns: что изменилось

Column, NoData и EmptyData используют `appearance="modern"` по умолчанию. У Column поиск занимает всю ширину, добавление находится в шапке, редактирование и удаление — в меню выбранного элемента. Без выбора это меню недоступно. Подтверждение удаления сохраняется, если приложение явно не отключило его через disableRemovePopconfirm.

Список компактнее, выбор не резервирует место под кнопки и не меняет ширину текста. Клавиатура позволяет выбирать строку, менять ширину колонки и сворачивать её. Перетаскивание границы только изменяет ширину; для сворачивания мышью используйте отдельную кнопку со стрелкой. Пользовательский title остаётся ReactNode: кнопки и их поведение задаёт приложение.

NoData означает отсутствие данных, EmptyData — ожидание выбора. Их content заменяет стандартное содержимое целиком.

### Как сохранить прежнее оформление

Добавьте appearance к существующим вызовам; остальные параметры оставьте прежними:

```tsx
<Column {...columnProps} appearance="classic" />
<NoData appearance="classic" />
<EmptyData appearance="classic" />
```

Classic сохраняет прежнее оформление и размещение действий. Его наличие не отменяет проверку размеров: высота рабочих областей теперь определяется родителем.

### Высота, тема и пользовательские стили

Контейнер задаёт доступную высоту. Шапка Column занимает место по содержимому, список получает остаток и прокручивается внутри. Проверьте старые обёртки с вычислениями вроде `calc(100vh - ...)`: вложенной колонке не нужно отдельно вычитать высоту шапки.

```tsx
<div style={{ display: 'flex', gap: 16, height: 560, minHeight: 0 }}>
  <Column {...columnProps} />
  <div style={{ flex: 1, minWidth: 240, minHeight: 0 }}>
    <EmptyData />
  </div>
</div>
```

Новый вид использует CSS-переменные Ant Design. Область должна наследовать переменные активной темы ConfigProvider. Пример настройки области:

```tsx
<ConfigProvider theme={{ cssVar: { key: 'application-theme' } }}>
  <div className="application-theme">{/* Рабочие области UI-кита */}</div>
</ConfigProvider>
```

Проверьте собственные CSS-переопределения внутренних классов: расположение действий и шапки изменилось. Для независимых колонок используйте разные columnKey — ширина сохраняется в localStorage. Длинные строки и подсказки по-прежнему оформляет renderItems.

Для счётчика результатов передайте Column общее число до фильтрации через totalItemsCount. selectedItemId остаётся строкой; пустая строка означает отсутствие выбора. После удаления выбранного элемента сбросьте выбор в приложении.

## SearchInput: что нового

Добавлены локальное оформление иконки и доступное название поля. aria-label имеет приоритет, затем используется placeholder, затем «Поиск». Пользовательский className сохраняется.

allowClear и prefix теперь можно явно переопределить стандартными Input props. Раньше обёртка всегда включала очистку и свою иконку, даже если приложение передавало другие значения. Проверьте вызовы, где такие параметры уже присутствуют: теперь они начнут действовать.

Поиск при вводе, по Enter и debounce реализует приложение. SearchInput не добавляет новую фильтрацию или задержку. Для узких областей используйте короткую подсказку, например «Найти…», и отдельное пояснение доступных полей.

## ConfigTable: новый вид и прежние настройки

По умолчанию используется modern: спокойная поверхность, компактная таблица (size="small"), перенос панели на узкой ширине и горизонтальная прокрутка широкой таблицы. Кнопка поиска подписана «Найти», добавление имеет иконку. Поиск выполняется по Enter, кнопке и при очистке.

Курсор обычных строк больше не обещает действие клика. Если приложение использует onRow для открытия записи, задайте соответствующий курсор своим классом.

Для прежнего вида передайте `appearance="classic"`. Переданные columns, size, scroll, pagination, rowSelection, locale и остальные Table props продолжают переопределять настройки обёртки. Пользовательский className объединяется с классом таблицы. Для фиксированной шапки используйте scroll.y, для плотности — size; отдельный новый API для них не нужен.

### Счётчик и пустые результаты

Новые параметры необязательны:

- totalItemsCount — общее число до фильтрации; включает дополнительный счётчик.
- filteredItemsCount — число совпадений при серверной пагинации. Без него используется dataSource.length, поэтому на серверной странице его нужно передавать явно.
- searchValue — выполненный запрос для внешнего управления, не черновик ввода. Родитель обновляет его при onSearch.
- onResetSearch — сброс поиска в приложении. Если обработчика нет, кнопка сброса вызывает onSearch с пустой строкой.

При пустом списке отображается «Данных пока нет», при выполненном непустом запросе — «Ничего не найдено» и кнопка сброса. locale.emptyText позволяет заменить это содержимое. Компонент сам не восстанавливает dataSource: это делает родитель.

Пример локальной фильтрации:

```tsx
import { useState } from 'react';
import { ConfigTable } from 'isp-ui-kit';

const modules = [
  { id: '1', name: 'Обработка сообщений' },
  { id: '2', name: 'Доставка уведомлений' },
];

export function ModuleTable() {
  const [query, setQuery] = useState('');
  const filtered = modules.filter((row) =>
    row.name.toLowerCase().includes(query.toLowerCase()),
  );

  return (
    <ConfigTable
      rowKey="id"
      columns={[{ title: 'Модуль', dataIndex: 'name' }]}
      dataSource={filtered}
      totalItemsCount={modules.length}
      searchValue={query}
      onSearch={setQuery}
      onResetSearch={() => setQuery('')}
      isAddBtn={false}
    />
  );
}
```

Без searchValue таблица самостоятельно отслеживает отправленный запрос, а данные всё равно обновляет приложение. Если поиск управляется снаружи таблицы, передавайте searchValue, чтобы счётчик и пустое состояние соответствовали данным.

### Панель выбранных строк

Панель появляется при непустом rowSelection.selectedRowKeys. selectionActions принимает действия приложения, onClearSelection снимает выбор во внешнем состоянии. Эти параметры необязательны и не назначают массовые действия автоматически.

Для выбора на нескольких страницах используйте стандартный preserveSelectedRowKeys. selectedRowKeys может включать записи, которых нет на текущей странице: массовое действие должно работать с ключами, а не только с видимым dataSource.

## Базовые поля: улучшения без отдельного дизайна

Обновлены FormInput, FormInputNumber, FormInputPassword, FormTextArea и FormSecretTextArea.

Обязательность теперь показывает стандартный Form.Item, а не звёздочка за пределами подписи. Поля получают связь label/htmlFor, aria-required, aria-invalid и описание ошибки/подсказки. Если приложение уже задаёт id, он сохраняется. controlClassName объединяется с formItemProps.className.

Сообщение React Hook Form при ошибке имеет приоритет над formItemProps.help и validateStatus. Если раньше приложение переопределяло ошибку этими параметрами, проверьте такой сценарий. Чтобы заменить текст ошибки, задавайте его в rules или через API React Hook Form.

У SecretTextArea кнопка переключения видимости получила доступное название, связь с полем и состояние aria-pressed. При disabled она недоступна; отступ справа предотвращает перекрытие текста кнопкой. Пользовательский className сохраняется.

### Сохранённые defaults и новые опции

`trimOnBlur=true` у четырёх текстовых полей, включая пароль и секретное значение. Для новых форм, где пробелы значимы, явно отключите обрезку:

```tsx
<FormInputPassword
  control={control}
  name="password"
  label="Пароль"
  trimOnBlur={false}
/>
```

`forwardEvents=false` у всех пяти полей. Это сохраняет прежнее поведение, когда onChange/onBlur приложения перекрывались обработчиками React Hook Form. Чтобы получать события, включите опцию:

```tsx
<FormInput
  control={control}
  name="name"
  label="Название"
  forwardEvents
  onChange={handleNameChange}
  onBlur={handleNameBlur}
/>
```

Сначала обновляется React Hook Form, затем вызывается обработчик приложения — один раз на событие. Обрезка на blur не вызывает дополнительный пользовательский onChange. onBlur получает исходное событие браузера; его target.value может содержать пробелы, даже если значение формы уже нормализовано.

Не включайте forwardEvents массово без просмотра обработчиков: ранее неработавшие callback-функции могут содержать сетевые запросы или другие побочные действия. Старые вызовы без опции менять не требуется.

FormInputPassword теперь принимает PasswordProps Ant Design, расширяющий прежний InputProps. Можно передавать visibilityToggle и iconRender. Существующие параметры не удалены.

## Порядок перехода приложения

1. Обновите пакет до версии, в которой опубликованы эти изменения. Эта статья не задаёт номер версии; сверяйтесь с CHANGELOG и peerDependencies выбранной версии.
2. Проверьте ThreeColumns и ConfigTable. При необходимости временно включите classic и переносите рабочие области по одной.
3. Сверьте высоту родителя, наследование темы, пользовательские стили и переопределения Table props.
4. Проверьте поиск, сброс, выбор на разных страницах, CRUD и загрузку на реальных данных.
5. Базовые поля оставьте с прежними defaults. Включайте trimOnBlur=false и forwardEvents только там, где это нужно приложению.
6. Проверьте отправку формы, валидацию, фокус первой ошибки, disabled/readOnly и видимость секретов. Не выводите реальные пароли и токены в логах проверки.

## Где посмотреть и что уже проверено

В Storybook доступны «Редизайн/Обзор», «Редизайн/Базовые поля», «Редизайн/Совместимость полей», Layout/ThreeColumns, Components/SearchInput и Components/ConfigTable.

Проверены TypeScript, ESLint по изменённым исходникам, сборки библиотеки и Storybook. Для базовых полей дополнительно проверены присваиваемость прежних типов параметров, обрезка/сохранение пробелов, отсутствие дублирования событий и фокус ошибок InputNumber/SecretTextArea. Для таблицы проверены поиск, очистка, выбор, пагинация, плотность и фиксированная шапка; рабочие области проверены в узкой области и тёмной теме.

Эти проверки покрывают компоненты и демонстрационные сценарии. Перед выпуском приложения остаётся проверить его собственные обёртки, CSS, обработчики и работу с API.

## Следующая итерация: поля выбора

Обновлены FormSelect, FormTreeSelect и FormAutoComplete. Они сохраняют стандартный вид Ant Design и теперь используют ту же доступную обёртку, что и базовые поля. Обязательность показывает Form.Item; подписи, подсказки и ошибки связаны с полями. При ошибке React Hook Form его сообщение имеет приоритет над formItemProps.help/validateStatus.

У FormSelect пользовательский onChange уже работал — он продолжает вызываться без новых параметров. При очистке одиночного Select undefined, как прежде, превращается в null. forwardEvents=true дополнительно включает пользовательский onBlur; onChange не дублируется.

У FormTreeSelect и FormAutoComplete onChange/onBlur приложения ранее перекрывались. Их передача включается явно через forwardEvents=true; без него старое поведение сохранено. TreeSelect не получает нового преобразования значений после очистки.

AutoComplete сохраняет прежнюю фильтрацию по value и обрезку пробелов на blur. trimOnBlur=false позволяет оставить пробелы. formItemProps и controlClassName теперь применяются к обёртке Form.Item: если вы передавали их раньше, проверьте эффект — ранее AutoComplete их не использовал для оформления поля.

Рабочая композиция находится в «Редизайн/Поля выбора». Переключатели и даты описаны в следующем разделе.

## Переключатели и даты

Обновлены FormCheckbox, FormRadioGroup, FormSwitch, FormDatePicker и FormRangeDatePicker. Базовый вид Ant Design сохранён. Checkbox оставляет подпись рядом с флажком; RadioGroup получает доступное имя и фокус первого доступного варианта при ошибке. Подписи и сообщения связаны с полями через BaseField. Сообщение ошибки React Hook Form имеет приоритет над formItemProps.help/validateStatus.

Переключатели сохраняют boolean; RadioGroup сохраняет items.value без нового преобразования. Пользовательские onChange/onBlur по умолчанию перекрываются обработчиками формы, как прежде. forwardEvents=true явно включает их передачу после React Hook Form. При включении проверьте ранее неработавшие callbacks на побочные действия.

У дат сохраняются русская локаль, format по умолчанию DD.MM.YYYY, saveDateFormat по умолчанию YYYY-MM-DDTHH:mm:ssZ и часовой пояс Europe/Moscow. Формат хранения менять не требуется. Дата хранится строкой, период — массивом строк; очистка сохраняет undefined. RangeDatePicker поддерживает прежние отдельные id начала и конца диапазона.

В старом API переданный onChange дат заменяет внутреннее сохранение значения. По умолчанию это сохранено: если приложение передаёт callback, оно должно обновлять форму самостоятельно. Для совместного выполнения включите forwardEvents=true — компонент сохранит строку или массив строк, затем вызовет onChange с исходными аргументами Ant Design (Dayjs и строкой показа). Новый callback не получает сериализованную строку формы вместо Dayjs.

Пример включения без смены формата:

```tsx
<FormDatePicker
  control={control}
  name="schedule.date"
  label="Дата запуска"
  forwardEvents
  onChange={(date) => handleDateSelected(date)}
/>
```

Композиция доступна в «Редизайн/Переключатели и даты». Сложные формы, редакторы и каркас приложения остаются следующими этапами.

## ConfigForm: структура и сохранение

В ConfigForm обновлена композиция формы. Поля сохраняют базовый вид Ant Design; массивы и словари получили заголовки групп, строки массива — подписи и доступные названия удаления. В Storybook доступны заполненная форма, required, асинхронное сохранение, ограниченная высота, пустая конфигурация, пустые и загружаемые варианты, изменение состава полей.

Изменения поведения:

- Сохранение работает через submit формы, в том числе Enter в однострочном поле. Внешний onSubmit по-прежнему получает только валидные значения.
- Если onSubmit возвращает Promise, кнопка показывает загрузку, повторный submit блокируется до завершения. Обработку ответа и ошибок API продолжает выполнять приложение.
- Пустой Select больше не заменяется вечным скелетоном. Поле остаётся в модели и проходит required; индикатор loading зависит от isLoading/isFetching источника. Запросы используют прежний crudApi[config].useGetListQuery().
- Высота не привязана к окну. В ограниченной области задайте высоту родителю; поля будут прокручиваться внутри. Без заданной высоты форма растёт по содержимому.
- Конфигурация без полей показывает пустое состояние и недоступное сохранение.

Прежние ключи и значения сохранены: data[0] для загрузки, id для одиночных полей, name для массивов и объектов. Не заменяйте data массивом другого формата при переходе. Обновление data запускает reset, поэтому стабильность ссылки на данные остаётся важной. Скрытые поля сохраняются в модели по прежним defaults React Hook Form. Автоматически применяются required и minRows/maxRows TextArea; ранее неиспользуемые ограничения min/max/minLength/maxLength не включаются этой итерацией.

FormArrayMap, FormObjectMap, редакторы и каркас приложения ещё остаются в плане редизайна. PcsKit не изменён.

## FormArrayMap и FormObjectMap

Редакторы вложенных коллекций стали компактнее: удаление теперь текстовой кнопкой с именованным действием, добавление — кнопкой с текстом. В узком контейнере ключ словаря переносится над значением; Input и Button сохраняют стандартный вид Ant Design в обеих темах. У FormArrayMap больше нет фиксированного чёрного цвета подписей.

Исправлена синхронизация: reset и setValue теперь заменяют видимые строки даже после первого заполнения. Раньше новая запись могла сохраняться в модели, пока на экране оставались старые значения. Пустые добавленные строки остаются черновиками, пока вы не начнёте ввод; они очищаются при внешнем обновлении. Строки получили стабильные ключи, чтобы удаление не перемещало фокус к другой записи.

Прежние преобразования сохранены:

- FormArrayMap показывает примитивы строками; после редактирования передаёт строки и исключает пустые строки. До редактирования исходные числа не преобразуются в модели.
- FormObjectMap передаёт словарь; пустой ключ исключается, пустое значение допускается. Повторяющиеся ключи по-прежнему разрешены, значение последней строки побеждает.
- Оба компонента обрезают пробелы при потере фокуса.

В FormArrayMap добавлен необязательный disabled (по умолчанию false), блокирующий поля и добавление/удаление. FormObjectMap сохраняет прежний disabled. Ошибки React Hook Form через setError теперь видны у коллекции; поля связаны с сообщением, фокус ошибки указывает на первое поле, а в пустой коллекции — на добавление. Свойства rules FormArrayMap не начинают применяться автоматически: это изменило бы ранее работающие формы. Переданные formItemProps и controlClassName сохранены.

Примеры находятся в «Редизайн/Массивы и словари», «FormComponents/FormArrayMap» и «FormComponents/FormObjectMap». FormCodeEditor также обновлён, см. следующий раздел. ReactJsonView оставлен отдельным legacy-компонентом без изменений и исключён из редизайна. PcsKit не изменён.

## FormCodeEditor: надёжная загрузка Monaco

Загрузка редактора теперь проходит через инициализацию Monaco и имеет явные состояния ожидания, ошибки и повторной попытки. На загрузку и монтирование отведено 20 секунд; loadTimeoutMs позволяет изменить предел. При размонтировании таймер и подписка blur освобождаются, поздний результат загрузки не обновляет состояние компонента. Высота резервируется заранее, включая loading и ошибку.

Monaco остаётся peer dependency приложения. Workers зависят от сборщика и должны быть настроены приложением до первого редактора. В Storybook они собираются Vite локально; это настройка примера, она не переносится автоматически в приложение вместе с библиотекой. Для Vite образец всех workers находится в `.storybook/monacoWorkers.ts`: editor, JSON, CSS, HTML и JavaScript/TypeScript.

Настройку workers выполняйте явным вызовом функции до загрузки Monaco. Один побочный импорт может быть удалён при оптимизации сборки; этот случай проверен и исправлен в Storybook.

При особой схеме загрузки передайте стабильную функцию loadMonaco, возвращающую модуль Monaco. Например, после настройки MonacoEnvironment:

```tsx
const loadMonaco = () => import('monaco-editor');

<FormCodeEditor
  control={control}
  name="configuration"
  language="json"
  loadMonaco={loadMonaco}
  loadTimeoutMs={30000}
/>;
```

Не объявляйте loadMonaco заново внутри каждого render: новая функция запускает новую попытку загрузки. Не пытайтесь переключать разные версии Monaco между редакторами: loader из @monaco-editor/react общий для приложения. Повторная попытка переиспользует уже загруженные модули и повторяет загрузку источника; при некорректных URL workers нужно исправить настройку приложения.

Совместимость сохранена: height по умолчанию 400px, language=javascript, disable=false, форматирование корректного JSON на blur. Переданные options имеют приоритет, включая options.readOnly над disable. Невалидный JSON остаётся исходным текстом. Пользовательский onChange по-прежнему перекрывает запись в React Hook Form, onMount — внутреннее форматирование. Новый forwardEvents=true позволяет явно объединить обработчики с React Hook Form и форматированием. Свойства rules не включаются автоматически; ошибки через setError отображаются у редактора.

label и controlClassName теперь используются для подписи и оформления внешнего Form.Item. При переходе учитывайте место подписи: height задаёт высоту самого редактора. Существующие theme, path, beforeMount, options, loading и callbacks Editor сохраняются. automaticLayout включён по умолчанию, его можно переопределить через options.

В «FormComponents/FormCodeEditor» добавлены реальная загрузка и сохранение, медленный источник, отказ первой попытки с восстановлением, readonly, размонтирование во время загрузки и JavaScript с worker. Проверка сборки не заменяет проверку Monaco в приложении с его сборщиком и политикой загрузки ресурсов.

## 8. Навигация: LayoutMenu и LayoutSider

Существующие обязательные props и маршрутизация сохранены. LayoutMenu получил необязательные theme (по умолчанию light) и inlineCollapsed для отдельного меню; внутри LayoutSider состояние сворачивания наследуется от Ant Design. Для тёмной панели задайте theme="dark" обоим компонентам.

Default ширины LayoutSider — 250 px, высоты — calc(100vh - 45px), collapsible — true. В панели с собственной высотой используйте style={{ height: '100%' }}. Теперь прокручивается содержимое, а кнопка сворачивания остаётся внизу этой панели. Если CSS приложения обращался к скроллу самого aside, перенесите его на .ant-layout-sider-children внутри .layout-sider.

```tsx
import { useState } from 'react';
import { LayoutMenu, LayoutSider } from 'isp-ui-kit';

function Navigation() {
  const [collapsed, setCollapsed] = useState(false);
  const [path, setPath] = useState('/modules');

  return (
    <div style={{ display: 'flex', height: 480 }}>
      <LayoutSider
        collapsed={collapsed}
        onCollapse={setCollapsed}
        style={{ height: '100%' }}
      >
        <LayoutMenu
          currentPath={path}
          menuConfig={[
            { key: 'modules', label: 'Модули', permissions: [] },
            { key: 'users', label: 'Пользователи', permissions: [] },
          ]}
          onHideMenuItem={() => false}
          onClickItem={({ key }) => setPath(`/${key}`)}
        />
      </LayoutSider>
      <main style={{ minWidth: 0, padding: 16 }}>{path}</main>
    </div>
  );
}
```

В примере путь хранится локально; в приложении используйте свой router. currentPath по-прежнему сопоставляется по первому сегменту с key или route; вложенный пункт users выбирается через /users. onHideMenuItem возвращает true для скрытия и получает строку либо массив permissions. Начально открытые группы определяет defaultOpenKeys; автоматическое раскрытие при последующей смене пути не добавлено.

trigger={null} и собственный trigger сохраняют приоритет. Стандартная кнопка поддерживает Enter/Space. Собственный className теперь дополняет layout-sider, поэтому оформление кита сохраняется вместе с классом приложения. Публичный onCollapse остаётся стандартным callback Ant Design. ReactJsonView и PcsKit не менялись.

Подробные рабочие примеры key, route, нескольких URL и вложенных маршрутов: [LayoutMenu — маршруты, ключи и переходы](layout-navigation.md). В Storybook они доступны в документации LayoutMenu и историях «Key, route и несколько URL одного раздела» и «Вложенные URL и адаптер маршрутов».

## 9. Главная и служебные страницы

HomePage, ErrorPage и NotFoundPage сохраняют children и получают необязательные style и className. Для размещения под шапкой передайте style={{ height: '100%' }} и задайте высоту родителю. Высота HomePage по умолчанию остаётся 100%, ErrorPage/NotFoundPage — 100vh. Прокрутка происходит внутри страницы.

HomePage больше не увеличивает шрифт children через vw/vh. Заголовки и крупный приветственный текст теперь явно оформляет приложение. backgroundImage сохраняется; фон центрируется с cover и без повторения, style позволяет вернуть прежний масштаб/повторение. В ErrorPage иллюстрация 500 заменена стандартным значком и заголовком «Ошибка 500». NotFoundPage сохраняет сообщение, добавляет код 404 и пояснение; absolute-центрирование заменено центрированием в контейнере. Старые CSS-селекторы на h2 NotFoundPage нужно перевести на h1.

Действия страниц остаются полностью пользовательскими; компонент не вызывает API и не выполняет переход самостоятельно. Полный пример встраивания: [Главная и служебные страницы](layout-pages.md). В Storybook — «Layout/Pages/Обзор» и «Редизайн/Приложение»; общий пример включает таблицу, форму, три колонки и служебные состояния. PcsKit и ReactJsonView не затронуты.

## 10. Исправления хуков и утилит

Сигнатуры useAuth сохранены. Статус теперь меняется только после успешного HTTP-ответа и разбора тела: ошибка входа больше не выставляет isLogged=true, ошибка выхода не сбрасывает успешную авторизацию. isLoading остаётся true до завершения всех запросов этого экземпляра. Форматы JSON-ошибок прежние; текстовое/пустое тело HTTP-ошибки доступно как текст/null вместо вторичной ошибки JSON. Это локальный статус операции, а не проверка доступа или восстановление сессии. Подробности: [useAuth](auth-hook.md).

getConfigProperty при отсутствии window возвращает defaultValue, сохраняя существующие false, 0, пустую строку, null и undefined в браузерной конфигурации. Текстовые утилиты учитывают только собственные свойства словаря/параметров и подставляют имена и значения буквально. Пустой текст по-прежнему сохраняется; verifyTextKey для него возвращает false. При отсутствующем словаре fallback по-прежнему возвращается без подстановки.
