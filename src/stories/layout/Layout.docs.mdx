## Интеграция с React Router (v6+)

Ниже — согласованный пример трёх файлов приложения: маршруты, конфигурация меню и каркас с `Outlet`. Он использует `react-router-dom` v6. Router устанавливается в приложении, а не в UI-ките. Если приложение уже обёрнуто в `BrowserRouter` или `RouterProvider`, второй router не добавляйте.

React Router выводит дочернюю страницу в `Outlet`; `useLocation().pathname` обновляет меню при переходах, включая Back/Forward. `useNavigate` меняет адрес после выбора пункта. См. [официальную документацию React Router v6](https://reactrouter.com/6.30.1/start/overview).

### Ключ пункта, route и адрес страницы

У LayoutMenu `key` — уникальный идентификатор пункта во всём дереве. `route` — необязательный алиас **первого сегмента** пути, а не адрес для перехода. Например, `key: 'users'` подходит для `/users/42`, а `key: 'people', route: 'users'` выделяет people на том же URL. В route передаётся `users`, без начального `/`.

Для `/settings/profile` первый сегмент — settings. Поэтому передача полного pathname выделит родительскую группу, а не profile. В этом примере приложение преобразует pathname в логический `menuPath`: `/settings/profile` → `/profile`. Таблица `destinationByKey` отдельно определяет, куда переходить по клику. Она не добавляет новое свойство в API кита.

### menu.ts

```tsx
import type { ConfigMenuItemType } from 'isp-ui-kit';

export const menuConfig: ConfigMenuItemType[] = [
  { key: 'dashboard', label: 'Дашборд', permissions: [] },
  { key: 'users', label: 'Пользователи', permissions: [] },
  {
    key: 'settings',
    label: 'Настройки',
    permissions: [],
    children: [
      { key: 'profile', label: 'Профиль', permissions: [] },
      { key: 'security', label: 'Безопасность', permissions: [] },
    ],
  },
];

export const destinationByKey: Record<string, string> = {
  dashboard: '/dashboard',
  users: '/users',
  profile: '/settings/profile',
  security: '/settings/security',
};

export function getMenuPath(pathname: string): string {
  const selectedKey = Object.keys(destinationByKey).find((key) => {
    const destination = destinationByKey[key];
    return pathname === destination || pathname.startsWith(`${destination}/`);
  });
  return selectedKey ? `/${selectedKey}` : '/__no_menu_match__';
}
```

Проверка границы сегмента не путает `/users/42` с `/users-archive`. Для неизвестного адреса возвращается путь, которому не назначен ни один пункт. Если в приложении есть пересекающиеся разделы, например `/users` и `/users/archive`, сопоставляйте сначала более специфичный адрес или используйте совпадения маршрутов своего router.

### LayoutComponent.tsx

```tsx
import { useState } from 'react';
import { Layout } from 'antd';
import { LayoutMenu, LayoutSider } from 'isp-ui-kit';
import { Outlet, useLocation, useNavigate } from 'react-router-dom';
import { destinationByKey, getMenuPath, menuConfig } from './menu';

export default function LayoutComponent() {
  const [collapsed, setCollapsed] = useState(false);
  const { pathname } = useLocation();
  const navigate = useNavigate();
  const menuPath = getMenuPath(pathname);

  return (
    <Layout style={{ height: '100vh', minWidth: 0 }}>
      <LayoutSider
        collapsed={collapsed}
        onCollapse={setCollapsed}
        style={{ height: '100%' }}
      >
        <LayoutMenu
          key={menuPath}
          menuConfig={menuConfig}
          currentPath={menuPath}
          onHideMenuItem={() => false}
          onClickItem={({ key }) => {
            const destination = destinationByKey[key];
            if (destination) navigate(destination);
          }}
        />
      </LayoutSider>
      <Layout style={{ minWidth: 0, minHeight: 0 }}>
        <Layout.Header style={{ paddingInline: 24, background: 'transparent' }}>
          Управление сервисами
        </Layout.Header>
        <Layout.Content style={{ minWidth: 0, minHeight: 0, overflow: 'auto' }}>
          <Outlet />
        </Layout.Content>
      </Layout>
    </Layout>
  );
}
```

Прямые импорты LayoutMenu/LayoutSider доступны из `isp-ui-kit`. Дополнительный `marginLeft` не нужен: Ant Design Layout размещает Sider и содержимое рядом автоматически, включая свёрнутое состояние. Для тёмного Sider задайте `theme="dark"` и у LayoutMenu; алгоритм общей темы задаётся ConfigProvider приложения.

React `key={menuPath}` здесь намеренно пересоздаёт меню при смене раздела: заново применяет начальные `defaultOpenKeys`, раскрывает родительскую группу и очищает выбор на неизвестном адресе. Ручное раскрытие групп при смене раздела сбрасывается. При переходе `/users/42` → `/users/43` menuPath остаётся `/users`, и сброса нет. Это адаптер примера, логика самого LayoutMenu не менялась. Если важно сохранять ручное раскрытие между разделами, уберите remount и учитывайте текущее поведение defaultOpenKeys; управляемые openKeys пока не входят в API обёртки.

### App.tsx

```tsx
import { Button } from 'antd';
import {
  BrowserRouter,
  Link,
  Navigate,
  Route,
  Routes,
  useNavigate,
} from 'react-router-dom';
import { HomePage, NotFoundPage } from 'isp-ui-kit';
import LayoutComponent from './LayoutComponent';

const Dashboard = () => (
  <HomePage style={{ height: '100%' }}>
    <section>
      <h1>Дашборд</h1>
      <Link to="/users">Открыть пользователей</Link>
    </section>
  </HomePage>
);
const Users = () => (
  <section style={{ padding: 24 }}>
    <h1>Пользователи</h1>
    <Link to="/users/42">Открыть пользователя 42</Link>
  </section>
);
const UserDetails = () => (
  <section style={{ padding: 24 }}>
    <h1>Карточка пользователя</h1>
    <Link to="/users">К списку пользователей</Link>
  </section>
);
const Profile = () => (
  <section style={{ padding: 24 }}>
    <h1>Профиль</h1>
  </section>
);
const Security = () => (
  <section style={{ padding: 24 }}>
    <h1>Безопасность</h1>
  </section>
);

const MissingPage = () => {
  const navigate = useNavigate();
  return (
    <NotFoundPage style={{ height: '100%' }}>
      <Button type="primary" onClick={() => navigate('/dashboard')}>
        На главную
      </Button>
    </NotFoundPage>
  );
};

export function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<LayoutComponent />}>
          <Route index element={<Navigate to="/dashboard" replace />} />
          <Route path="dashboard" element={<Dashboard />} />
          <Route path="users" element={<Users />} />
          <Route path="users/:userId" element={<UserDetails />} />
          <Route path="settings/profile" element={<Profile />} />
          <Route path="settings/security" element={<Security />} />
          <Route path="*" element={<MissingPage />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}
```

`/` перенаправляется на `/dashboard` с replace, чтобы начальная страница соответствовала пункту меню. Страница пользователя сохраняет выделение users, профиль и безопасность выбирают соответствующих детей группы settings. Catch-all `*` показывает NotFoundPage внутри общего каркаса. Высота страницы 404 — 100% области под шапкой, а не дополнительные 100vh.

У этих маршрутов нет проверки авторизации: `onHideMenuItem={() => false}` показывает все пункты. Если приложение использует разрешения, передайте свой обработчик скрытия и сохраните проверку доступа в маршрутах приложения.

### Версии и проверка подключения

Пример использует API React Router 6: BrowserRouter, Routes, Route, Outlet и hooks из react-router-dom. В React Router 7 соответствующие API можно импортировать из react-router; проверьте установленную версию и существующий способ настройки router. Этот пример не является инструкцией обновлять зависимость приложения.

После подключения проверьте:

- прямое открытие `/settings/profile`: выбран профиль, группа настроек раскрыта;
- переход из страницы по Link и Back/Forward: выделение обновляется из pathname;
- `/users/42`: выбран users;
- неизвестный адрес: показана 404, предыдущий пункт не остаётся выбранным;
- сворачивание панели: содержимое не получает второй левый отступ;
- query/hash: меню получает pathname, например `/users`, а не строку `/users?tab=all`.
