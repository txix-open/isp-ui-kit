## Как читать Storybook

1. Откройте пример и выполните действие, например отправьте поиск или сохраните форму. Данные в этих примерах демонстрационные.
2. На странице **Docs** найдите описание, варианты использования и таблицу параметров, если она доступна. Параметры, которые приложение передаёт компоненту, в React называются props. Например, `dataSource` содержит строки таблицы, а `onSearch` — функцию, вызываемую при отправке поиска.
3. В панели **Controls** меняйте доступные параметры примера. В верхней панели переключайте тему и ширину, чтобы посмотреть, как компонент выглядит в разных условиях.

## Установка

```bash
npm install isp-ui-kit
```

В существующем приложении выбирайте версию кита явно и проверяйте её peerDependencies. Команда без версии устанавливает опубликованный latest; документация этой ветки может описывать ещё не выпущенные изменения.

Требования рабочей ветки берутся из package.json. Они не заменяют требования выбранного опубликованного релиза:

<Markdown>
  {'```json\n' +
    JSON.stringify(packageInfo.peerDependencies, null, 2) +
    '\n```'}
</Markdown>

Peer dependencies должны присутствовать в приложении и удовлетворять указанным диапазонам. Перед обновлением проверьте уже установленные React, React DOM и Ant Design; не обновляйте их независимо от совместимости приложения.

## Первое подключение

Используйте именованные импорты из корня пакета. Для собственных поверхностей кита включите CSS-переменные Ant Design и обеспечьте их наследование в рабочей области:

```tsx
import { useState } from 'react';
import { ConfigProvider } from 'antd';
import { SearchInput } from 'isp-ui-kit';

export function App() {
  const [query, setQuery] = useState('');

  return (
    <ConfigProvider theme={{ cssVar: { key: 'application-theme' } }}>
      <main className="application-theme" style={{ padding: 16 }}>
        <SearchInput
          value={query}
          onChange={(event) => setQuery(event.target.value)}
          placeholder="Найти сервис"
        />
      </main>
    </ConfigProvider>
  );
}
```

Пример сохраняет запрос в состоянии. Фильтрацию и debounce реализует приложение. Для полей формы нужен `control` из useForm; для Monaco — настройка workers. Эти сценарии описаны в соответствующих разделах.

## Разделы библиотеки

- [Components](?path=/docs/components-описание--docs) — поиск, таблицы и просмотр JSON.
- [FormComponents](?path=/docs/formcomponents-описание--docs) — поля, конфигурационные формы, коллекции и редактор кода.
- [Layout](?path=/docs/layout-описание--docs) — меню, рабочие колонки и служебные страницы.
- [Hooks](?path=/docs/hooks-описание--docs) — авторизация и её состояния.
- [Utils](?path=/docs/utils-описание--docs) — конфигурация, тексты и поиск маршрутов меню.

## Обновление существующего приложения

Для текущего редизайна используйте [руководство по переходу](?path=/docs/переход-на-версию-3-0-0--docs): новый вид по умолчанию, высота рабочих областей, события форм и приёмка приложения. Версия текущих исходников — 3.0.0; публикация пакета выполняется отдельно.

[Переход на 1.0.0](?path=/docs/переход-на-версию-1-0-0--docs) — архивная инструкция по изменению импортов, а не рекомендуемая версия для нового проекта. [Разработчикам](?path=/docs/разработчикам--docs) — локальный запуск, добавление компонентов, проверки и публикация кита.
