# Поля и формы

Поля соединяют Ant Design с React Hook Form: значение и ошибки принадлежат форме, а оформление остаётся базовым Ant Design. Используйте прямые именованные импорты из пакета.

## Подключение в приложении

```tsx
import { useState } from 'react';
import { Button } from 'antd';
import { useForm } from 'react-hook-form';
import { FormInput, FormTextArea } from 'isp-ui-kit';

type Values = { name: string; description: string };

export function ServiceForm() {
  const [saved, setSaved] = useState<Values | null>(null);
  const { control, handleSubmit, reset } = useForm<Values>({
    mode: 'onChange',
    defaultValues: { name: '', description: '' },
  });

  return (
    <form onSubmit={handleSubmit((values) => setSaved(values))}>
      <FormInput
        control={control}
        name="name"
        label="Название сервиса"
        rules={{
          required: { value: true, message: 'Введите название' },
          minLength: { value: 3, message: 'Минимум 3 символа' },
        }}
        formItemProps={{ extra: 'Название для отображения в списке' }}
      />
      <FormTextArea
        control={control}
        name="description"
        label="Описание"
        rows={3}
      />
      <Button type="primary" htmlType="submit">
        Сохранить
      </Button>
      <Button
        htmlType="button"
        onClick={() => {
          reset();
          setSaved(null);
        }}
      >
        Сбросить
      </Button>
      {saved && (
        <pre aria-label="Сохранённые данные">
          {JSON.stringify(saved, null, 2)}
        </pre>
      )}
    </form>
  );
}
```

Ошибки отображаются рядом с полем; повторно выводить `formState.errors` для этого не требуется. Начальные значения задаются через `defaultValues`, загрузка другой записи — через `reset`, отдельное изменение — через `setValue`. Не передавайте независимый value вместо значения React Hook Form.

## Общие свойства полей

- `control` — объект из useForm; `name` — путь в данных, например `service.name`.
- `label` — подпись. `controlClassName` относится к Form.Item, обычный className — к контролу.
- `rules` — правила React Hook Form. Обязательность задаётся как `required: { value: true, message: '...' }`.
- `formItemProps` — оформление Form.Item, подсказки `help` и `extra`. У полей с подписью в Form.Item свойство `formItemProps.label` имеет приоритет над label; у Checkbox label остаётся текстом рядом с флажком. Сообщение ошибки формы — над help. `formItemProps.required` меняет визуальную обязательность, а проверка задаётся через rules.
- `forwardEvents` по умолчанию false сохраняет прежнее поведение callbacks конкретного поля. true добавляет вызов ранее перекрытых обработчиков после обработчиков формы. У Select пользовательский onChange работает и без этой опции. У дат переданный onChange в прежнем режиме заменяет внутреннее сохранение; true объединяет их.
- `trimOnBlur` есть у текстовых полей и AutoComplete: true по умолчанию обрезает крайние пробелы при потере фокуса, false сохраняет ввод дословно. У чисел, выбора и дат этой опции нет.

Эти общие правила относятся к одиночным полям. У ConfigForm, FormArrayMap и FormObjectMap свои интерфейсы и ограничения, описанные ниже и на страницах компонентов.

## Текст и числа

- [FormInput](?path=/docs/formcomponents-forminput--docs) — однострочный текст.
- [FormTextArea](?path=/docs/formcomponents-formtextarea--docs) — многострочный текст, rows и autoSize.
- [FormInputNumber](?path=/docs/formcomponents-forminputnumber--docs) — число, min/max, шаг и форматирование; stringMode задаётся приложением.
- [FormInputPassword](?path=/docs/formcomponents-forminputpassword--docs) — пароль с переключением видимости; обрезку пробелов можно отключить.
- [FormSecretTextArea](?path=/docs/formcomponents-formsecrettextarea--docs) — многострочный текст с визуальным маскированием. Маскирование не шифрует и не меняет значение.

## Выбор и переключатели

- [FormSelect](?path=/docs/formcomponents-formselect--docs) — одиночный или множественный выбор; очистка одиночного значения сохраняет null.
- [FormAutoComplete](?path=/docs/formcomponents-formautocomplete--docs) — свободный текст с подсказками, а не ограниченный выбор из списка.
- [FormTreeSelect](?path=/docs/formcomponents-formtreeselect--docs) — выбор из treeData с вложенными узлами.
- [FormCheckbox](?path=/docs/formcomponents-formcheckbox--docs) и [FormSwitch](?path=/docs/formcomponents-formswitch--docs) — boolean.
- [FormRadioGroup](?path=/docs/formcomponents-formradiogroup--docs) — одно значение items.value; type="radio" или type="button".

## Даты

- [FormDatePicker](?path=/docs/formcomponents-formdatepicker--docs) — дата в виде строки в модели формы.
- [FormRangeDatePicker](?path=/docs/formcomponents-formrangedatepicker--docs) — массив строк начала и конца периода.

По умолчанию показ — DD.MM.YYYY, хранение — YYYY-MM-DDTHH:mm:ssZ в Europe/Moscow. `format` меняет отображение, `saveDateFormat` — сохраняемую строку; очистка даёт undefined. Начальные значения передавайте в формате хранения, а не как объекты Dayjs.

## Конфигурации и сложные данные

- [ConfigForm](?path=/docs/formcomponents-configform--docs) — строит форму по config.fields; начальные значения берёт из data[0]. Одиночные значения используют id, массивы и словари — name. Не все правила конфигурации реализованы: ограничения смотрите на странице компонента.
- [FormArrayMap](?path=/docs/formcomponents-formarraymap--docs) — массив редактируемых строк. Добавленная пустая строка остаётся черновиком, пустые значения исключаются при редактировании; числа после редактирования становятся строками.
- [FormObjectMap](?path=/docs/formcomponents-formobjectmap--docs) — словарь строковых ключей и значений. Пустой ключ исключается, при повторении ключа остаётся значение последней строки.
- [FormCodeEditor](?path=/docs/formcomponents-formcodeeditor--docs) — Monaco с загрузкой, ошибкой и повторной попыткой. Подключение Monaco и workers выполняется один раз в приложении; на странице есть примеры интеграции.

## Проверка и совместимость

Истории «Валидация» у одиночных полей заранее устанавливают демонстрационную ошибку через setError. Кнопка «Проверить и отправить» запускает реальные rules, «Сбросить» очищает форму. Примеры не отправляют данные на сервер.
