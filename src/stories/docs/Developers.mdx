# Для разработчиков

Эта статья описывает работу с репозиторием UI-кита. Для знакомства с компонентами начните с [введения](?path=/docs/введение--docs), а для интеграции с бэкендом — с [примера работы с данными API](?path=/docs/работа-с-данными-api--docs).

## Локальный запуск

Для разработки используйте Node.js 24, как в CI, и npm. Команды выполняются из корня репозитория:

```bash
npm ci
npm run storybook
```

Storybook по умолчанию доступен на порту 6006. `npm ci` устанавливает зависимости по package-lock.json; prepare настраивает Husky. При изменении зависимостей обновляйте package.json и lock-файл вместе.

## Структура проекта

- `src/components` — SearchInput, ConfigTable и JSON-просмотрщик.
- `src/FormComponents` — поля React Hook Form, ConfigForm и коллекции.
- `src/Layout` — навигация, колонки, пустые состояния и страницы.
- `src/PcsKit` — отдельная группа компонентов.
- `src/hooks`, `src/utils`, `src/cfg` — хуки, утилиты и общая конфигурация.
- `src/stories` — истории и MDX-статьи; `.storybook` — настройки демонстрации.
- `docs` — решения по дизайну, миграция и руководства, часть которых подключается в Storybook.
- `tests` — регрессионные проверки; способы запуска описаны в tests/README.md.
- `src/index.ts` — публичные экспорты пакета. `dist` — результат сборки, его не редактируют вручную.

Библиотека собирается Rollup в ESM, CommonJS и декларации TypeScript. Storybook использует React и Vite. Стили SCSS обрабатываются при сборке и включаются в JavaScript пакета.

## Добавление компонента

Следуйте структуре соседних компонентов: основной файл `ComponentName.tsx`, типы в отдельном файле, стили — `component-name.scss`. Сохраняйте принятую в папке форму имён Props/PropsType; не переименовывайте существующий API ради единого суффикса.

Для компонента общего назначения добавьте публичный экспорт в src/index.ts:

```tsx
import SearchInput from './components/SearchInput/SearchInput';
export { SearchInput };
```

Для компонента группы используйте её index-файл:

```tsx
// src/FormComponents/index.ts
export { default as FormInput } from './FormInput/FormInput';

// src/index.ts
export * from './FormComponents';
```

Публичные типы также должны быть экспортированы из корня. Потребитель использует:

```tsx
import { FormInput, SearchInput } from 'isp-ui-kit';
import type { FormInputProps } from 'isp-ui-kit';
```

В примерах для приложений используйте корень пакета. Глубокие импорты из `src` или `dist` зависят от внутренней структуры сборки.

## Реализация и стили

Вызывайте хуки без условий на верхнем уровне компонента. Эффекты выполняются после рендера; подписки, таймеры и другие ресурсы освобождайте в cleanup. Не выполняйте побочные действия во время рендера.

Используйте локальные классы и БЭМ-нейминг. Не вводите глобальные переопределения `.ant-*` ради одного компонента:

```scss
.user-profile {
  &__header {
    min-width: 0;
  }
}
```

Для работ по редизайну сверяйтесь с docs/design-system.md и docs/redesign-plan.md. Поля сохраняют базовое оформление Ant Design; поверхности наследуют токены темы. PcsKit исключён из визуального редизайна. В 3.0.0 ReactJsonView использует только новый JsonViewer; legacy-исходники и их зависимости удалены.

## Истории и документация

Истории лежат рядом с соответствующей группой в src/stories. Добавьте рабочий сценарий и существенные состояния: длинные данные, пустота, загрузка/ошибка, disabled/readOnly, ограниченные размеры и клавиатура. Обработчики демонстрации должны давать видимый результат.

Для примеров интеграции покажите входные данные, действие пользователя и данные, которые получит обработчик. Отдельно укажите, где приложение вызывает API и какое состояние пользователь видит при ошибке или пустом ответе.

Описания props сверяйте с типами и реализацией. При изменении defaults обновляйте документацию компонента и [руководство по переходу](?path=/docs/переход-на-версию-3-0-0--docs). Отделяйте требования рабочей ветки от уже опубликованных версий. Русские заголовки и ссылки проверяйте в собранном Storybook.

## Проверки перед передачей изменений

```bash
npx tsc --noEmit
npm run build
```

ESLint запускайте по изменённым исходникам. Например:

```bash
npx eslint src/components/SearchInput/SearchInput.tsx
```

Истории и .storybook исключены текущим eslint.config.mjs, а основной tsconfig исключает истории. Поэтому эти команды не подтверждают проверку типов и lint всех примеров.

Для отдельной проверки типов Storybook и браузерных проверок используйте:

```bash
npx tsc --project tsconfig.storybook.json
```

Эта конфигурация включает Vite-типы raw/worker-импортов и все истории, включая PcsKit. На текущем аудите 3.0.0 остаются три ошибки в историях PcsKit: nullable-дата и обращения from/to к PcsFilterSelectedLabelValue. Они не скрываются основным успешным tsc; исправление PcsKit не входит в область редизайна.

При изменении историй, MDX или общей рамки выполните:

```bash
npm run build-storybook
```

Проверьте затронутые примеры в браузере: темы, ширину/высоту, действия, клавиатуру и панель Accessibility. Утилиты проверяются командой `node --test tests/utils.test.mjs`; для useAuth и сценариев редизайна есть отдельные браузерные страницы в tests. В package.json нет скриптов test/lint — используйте реальные команды и tests/README.md.

## Версия и публикация

Выпуск — отдельный шаг после проверки и согласования изменений.

1. Назначьте версию, обновите package.json и package-lock.json, оформите отдельный раздел релиза в CHANGELOG.md. Версия текущих исходников — 3.0.0; публикация выполняется отдельно.
2. Выполните `npm run build` и `npm run check:package`, затем зафиксируйте изменения. Принятый формат сообщения коммита версии — `up version to X.Y.Z`.
3. После проверки коммита создайте и отправьте тег вида `vX.Y.Z`, соответствующий версии пакета.
4. Проверьте успешное выполнение `.github/workflows/main.yml` и опубликованную версию.

Workflow запускается при push тегов `v*`. Он использует Node.js 24, устанавливает Linux-бинарник Rollup, выполняет `npm ci` и собирает пакет. Проверка устанавливает архив `npm pack` во временное приложение и проверяет импорты ESM и CommonJS, типы TypeScript и клиентскую сборку Vite, в том числе через библиотеку-обёртку. После успешных проверок workflow передаёт этот архив в `npm publish`.
