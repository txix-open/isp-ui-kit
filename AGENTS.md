# Работа с isp-ui-kit

- Используйте Node.js 24, как в релизном workflow. Устанавливайте зависимости через `npm ci` и синхронизируйте `package.json` с `package-lock.json`.
- Публичные компоненты и типы подключаются именованными импортами из `isp-ui-kit`. При изменениях экспорта учитывайте прямых потребителей и связку `isp-admin-ui → isp-admin-ui-kit → isp-ui-kit`. Сборка поддерживает ESM и CommonJS.
- При изменении компонентов проверяйте связанные истории, светлую и тёмную темы и работу с клавиатуры. Правила оформления описаны в [docs/design-system.md](docs/design-system.md). Сохраняйте PcsKit вне редизайна без отдельного запроса.
- Для проверки пакета выполните `npm run build` и `npm run check:package`. Для изменений историй и документации выполните `npm run build-storybook`. Регрессионные сценарии описаны в [tests/README.md](tests/README.md).
- Изменения публичного поведения отражайте в [CHANGELOG.md](CHANGELOG.md) и [руководстве по миграции](docs/migration.md). Публикация в npm и отправка релизного тега требуют отдельного запроса.
